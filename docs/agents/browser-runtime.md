# Browser runtime

Read this before touching `services.browser`, the bundle's Playwright handling in `build.gradle.kts`, or bumping Playwright.

- The release bundle and the Docker image ship neither Playwright's `driver-bundle` (all-platform Node.js, ~194 MB) nor Chromium. `build.gradle.kts` filters the jar out of `playBundle`'s `playClasspath`, so it is in neither the bundle's `lib/` nor its `.classpath`; on the first browser call (or from Settings → Browser) JClaw downloads its platform's official Node.js, verifies it against the SHA-256 pinned in `services.browser.PlaywrightNode`, hands it to Playwright as `PLAYWRIGHT_NODEJS_PATH` in `Playwright.create`'s env map, then installs Chromium. Dev, tests and `play run` keep `driver-bundle` on the classpath. Docker puts both downloads on the data volume (`data/playwright-node`, `PLAYWRIGHT_BROWSERS_PATH=/app/data/pw-browsers`) so an image upgrade does not re-fetch them. Do not re-add a Chromium image stage: Playwright 1.63 installs at container runtime on the ubuntu:26.04 base on arm64 and amd64 (measured 2026-09-24).
- Scripts run on the same pinned Node without Chromium: `ScriptNode.resolve` takes `PLAYWRIGHT_NODEJS_PATH`, then the managed driver folder, then that download, and every Node download goes through `BrowserSetup.downloadNode`, whose lock lets the browser's setup and a script share one download and whose progress Settings → Browser shows. Its start arguments carry `--permission` and never an `--allow-*` flag, and the script goes in on stdin, never in argv.
- Because that volume outlives Playwright bumps, "is Chromium installed" is revision-exact (`BrowserSetup.chromiumInstalled`: an `INSTALLATION_COMPLETE` marker at each `browsers.json` revision), never "any `chromium*` directory". On a Playwright bump `PlaywrightNode.VERSION` must equal driver-bundle's `node --version` (`PlaywrightNodeTest.thePinnedVersionIsTheNodeThatDriverBundleShips` fails until it does); re-pin the five hashes from that release's `SHASUMS256.txt` — no test checks them. The chat's progress bar starts from the `Using tool: browser` status frame, because the `tool_call` frame arrives only after the call returns.
- The live-browser tests in `PlaywrightToolTest`, `JevRunTest`, `StealthFingerprintTest` and `StealthNetworkScreenTest` run only under `JCLAW_PLAYWRIGHT_TEST` (the two stealth classes also need `uv` and Patchright's Chromium), and only `./jclaw.sh test` sets it — it exports `1` when a `chromium_headless_shell-*` build is cached (`PLAYWRIGHT_BROWSERS_PATH`, else the platform cache), adding about 2 minutes, and otherwise prints one skip line. So `play autotest` and `./gradlew playAutotest -Ptests=PlaywrightToolTest` come back green having run none of them: export the flag yourself for a targeted run, or where Chromium lives outside those caches. `0` and `false` opt out; pre-push inherits whatever `./jclaw.sh test` decides.
