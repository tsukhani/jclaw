# Logging and retention

Read this before touching `EventLogger.record`, `utils.SecretRedactor`, or a cleanup job's retention window.

- `EventLogger.record` masks credentials with `utils.SecretRedactor` before the message reaches the log file or the `event_log` table: agents put keys on `exec` command lines and in tool arguments, and each call is logged twice (`exec: …` and `Executing tool … args: …`). Log anything that can carry a command, a URL or tool arguments through `EventLogger`, never `play.Logger` directly, which bypasses it. The redactor keeps the header or parameter name. A pattern only finds the name; `valueAfter` then follows the quoting to where the value ends (its own quote at the same escape depth, the quoted string it sits inside, or a shell word), because a regex cannot: widening a value's character class is how a tail leaks. Where two readings differ it takes the longer one and over-masks. It tells a count or a cursor from a credential by the name only (`tokens`, `tokenCount`, `page_token`), never by the value's shape. No pass trusts an earlier pass's mask as the end of a value: it scans again, since the earlier one may have stopped short. Its input is model-controlled, so the work stays linear: a pattern's quantifier is bounded or possessive, and each pass reads forward once, for the value and for the quotes before it (`SecretRedactorTest` times 500,000 characters of each trigger, bare and inside one long quoted string). Logged arguments are JSON inside JSON, so a quote arrives behind backslashes and `=`, `&`, `'` also arrive as `\u003d`, `\u0026`, `\u0027`; `aSecretIsMaskedWholeHoweverItsContextEscapesIt` writes a secret the way each context escapes it, and a new context belongs in that matrix. When reading `logs/application.log` or `event_log` rows written before the mask, never print an `exec:` or `args:` line.
- Retention is one resolver, `jobs.RetentionDays`: absent or blank → the caller's default; 0 or negative → `DISABLED`, and the job returns before it computes a cutoff — never a window, since a cutoff at or after now takes the whole table; over the caller's ceiling or non-numeric → the default plus a warn. The ceiling stays per-caller: the event log passes `NO_CEILING`, the rest 3650. `ConfigService` refuses `logs.retentionDays` below 1 and Settings pins `:min="1"`, so for that key the non-positive branch is a net for a value written around the API; `tasks.retentionDays` offers 0 as off.
