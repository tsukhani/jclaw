# Chrome bridge

Read this before touching `ChromeBridge*`, `ChromeControlTool`, `ChromeBridgePolicy`, `ChromeBridgeToken` or `chrome-extension/`.

- **The extension drives the operator's own signed-in browser**, so a page the agent opens is a page opened as the operator. Every rule below exists because the agent's reach is the operator's.
- **Policy lives on the JClaw side, never in the extension.** `ChromeBridgePolicy.visitRefusal` judges every navigation, and `ChromeControlTool` judges a tab again by its current address before it reads from it or acts on it, because a click can leave an allowed site. A read whose final address is off the list is discarded.
- **Loopback, private-network, malformed and credentialed URLs stay blocked even with allow-all.** The operator's browser is signed in to JClaw itself, so an agent reaching `localhost:9000` there would act as the operator. `SsrfGuard.assertUrlSafe` is the check; do not relax it for the main agent.
- **The allowlist and both overrides are `agent.<name>.chromeBridge.*` config rows.** They ride `AgentDeletionCascade` and the rename path for free, and only the operator-only `POST /api/config` writes them, so an agent cannot widen its own reach through `jclaw_api`. The two overrides are refused for any agent but `main` at write time (`ChromeBridgePolicy.rejectionFor`) and ignored for any other agent at read time, so a planted key does nothing.
- **A click waits for approval unless the extension's `read` flagged the element a plain link**, through `Tool.dangerous(argsJson, agent)`, an agent-aware overload the gate calls so that only `main` can be exempt. A plain link is an `<a>` with an `href` that is not `javascript:`. Everything else asks: buttons, form controls, a `<div>` with a click handler, and a ref that was never read. This is deliberately stricter than "is a form button": a script-driven control sends data without a form, and the extension cannot tell it from a harmless click. Still not caught: a link whose GET changes state (sign-out, a confirm link) and a link whose own script posts on click. `type` cannot submit, since the tool has no key press. The allowlist is the real boundary and the approval is a second check. Not yet tested on a real site.
- **The tool is opt-in for every agent, `main` included, and offered only on turns the owner reads alone** (`OPT_IN_FOR_EVERY_AGENT` and `OPERATOR_TURN_ONLY` in `ToolRegistry`). Page text goes to the model labelled untrusted; that is a nudge, not a defence against prompt injection.
- **The pairing token is a separate credential from `ApiToken`** and is stored as a hash. It travels in the first `hello` frame, never the URL, and the socket closes at 5 s if none arrives. The socket checks that `Origin` starts with `chrome-extension://`, which a web page cannot forge.
- **One extension at a time.** A second connection replaces the first and fails what was waiting on it. A request waits on an untimed `get()` while a `RetryScheduler` task supplies the deadline, because a timed park on many virtual threads is JDK-8373224.
- **Tests that attach a fake extension hold `ChromeBridgeSync`**, since the connection is a process-global. `ChromeBridgeSocketTest` is the only test that opens a real WebSocket to the app.
- **Not built:** screenshots through the tool (the extension supports them), and a check that the extension's id matches the one that paired.
